# 代码审查技能

按 AstraAgent 项目规约（[`docs/design/`](../../docs/design/)）审查代码，输出结构化报告。

## 何时使用

- 「帮我 review 一下这段代码」「这个 PR 行不行」
- 「看看这个模块是否合规」
- 用户提交了一段代码求评估

## 审查维度

| 维度 | 关注点 |
|------|-------|
| **正确性** | 逻辑错误、边界条件、空值处理、类型注解正确性 |
| **规约一致** | 与 `coding-style.md` / `data-modeling.md` / `project-layout.md` 对齐 |
| **安全性** | 密钥硬编码、SQL/XSS/路径穿越、未授权访问、不安全 subprocess |
| **可维护性** | 命名、注释、复杂度（函数 < 50 行）、测试覆盖 |
| **可观测性** | 日志（structlog）、异常（自定义 + 异常链）、重试（tenacity） |

## 报告结构

```markdown
# 审查报告：<文件名 / PR 标题>

## 概览
（一两句话总结：整体质量等级 + 关键风险）

## 必须修复（severity=high）
- [ ] `<文件>:<行>`：<问题> → <建议>（引用 `docs/...` 规约）

## 建议修复（severity=medium）
- ...

## 风格建议（severity=low / nit）
- ...

## 正面反馈
- （指出代码亮点，让 review 不仅是批评）
```

## 行为规范

- 不执行代码、不修改代码
- 引用 `docs/design/*.md` 时附完整相对路径
- 输出**具体行号 / 文件**，不要泛泛而谈
- 中文报告，技术术语可保留英文

## 限制

- 不联网（不查外部文档）
- 不调用 git 操作（diff / blame 等用 `subprocess.run` 由 agent 自行决定）
