# Agent 执行设计与重构边界

现有 agent 的主要复杂度来自职责交叉：HTTP 路由拼附件、解析 SDK 事件、写统计、管理子任务并保存失败；后台生产者再次解析事件推断运行状态。`getattr`、空字典和宽泛异常让这些模块缺少可信的内部契约。

重构以可读的主流程为准：外部数据在入口检查，内部依赖明确类型；错误在能够处理它的边界处理，程序错误保留原始异常。保留现有 deepagents / LangGraph 及前端 SSE 协议，不另建一套编排框架。

## 一轮对话

```text
HTTP 请求
  routes/chat.py         校验会话归属，取得会话锁
  attachments.py         准备统一的图片、文档、沙箱文件输入
  stream_runs.start_run  接管锁，取得 PG 执行租约，启动后台任务
    chat_execution      调用模型流，记录指标和子任务，处理产物和失败
      core.agent        调用已编译的 LangGraph
      stream_events     SDK 事件 → 前端展示事件，维护主回复状态
  stream_runs           保存最终状态，发布一次 done，释放租约和锁
SSE 订阅者               读取有界回放；断线不取消后台任务
```

恢复审批、问题回答和故障恢复直接提交 `Command` 或 `None`，共用同一执行器，不制造新的用户消息。

## 明确的契约

| 边界 | 契约 |
| --- | --- |
| HTTP → 执行 | 用户上下文必填；模型输入已准备完成，原始用户文本单独传入用于失败记录 |
| SDK → 展示 | 消费 LangChain v2 事件及 `AIMessage` / `AIMessageChunk`，不兼容任意假对象 |
| 执行 → 后台 | 只产生展示事件；错误载荷由 `capture_failure` 构造；不产生 `done` |
| 后台 → 持久化 | 自然结束为 completed；待审批为 waiting；异常为 failed；用户停止为 stopped；其他取消为 interrupted |
| 锁交接 | 同步调用、审批恢复与检查点恢复也先取得 PG 租约；调用 `start_run` 即交出已有租约及本地锁，提交失败也由它释放 |
| 子任务 | 子事件计入指标和独立记录；通过祖先 run_id 隔离，不进入主回复解析器 |
| 附件 | 类型取服务端保存格式；图片可内联，文档可抽文；编辑使用容器路径；传输不阻塞事件循环 |

## 错误与生命周期

- 配置和框架契约错误直接暴露，禁止用 `None`、空列表或成功文本掩盖。
- 工具的预期输入错误使用 `ToolException`；模型参数校验、明确 I/O 和 HTTP 错误可以成为 `ToolMessage(status="error")`。`TypeError`、`AttributeError` 等程序错误结束本轮。
- 只读工具仅重试短暂连接或超时错误；写入操作不自动重放。模型重试按异常类型判断，不匹配异常类名字符串。
- 待办清单记录进度，任务工具由模型按目标选择；不按待办数量强迫委派。
- 失败或取消先保存最近一段输出，再通知订阅者；保留原始框架检查点，避免破坏工具调用协议。
- 初始化也在资源清理范围内；一个资源关闭失败仍继续关闭其他资源，关闭错误继续向上传播。
- 任务收尾使用一个独立清理任务；停止和关闭期间的重复取消不能跳过状态保存、租约关闭或锁释放。
- 首次取消请求记录来源：用户停止、服务关闭或执行租约丢失。重复取消不覆盖原因；无法确定来源的旧记录保持原值，不推测成用户停止。
- SSE 断线只结束订阅；服务进程关闭仍会取消后台任务。长任务使用 `run_api.py`，源码热重载不能替代进程外任务队列。
- 前端流结束后先查询执行状态：后台仍在运行时保留现场并允许重新连接；确认结束后，以已保存的历史校准工具结果。恢复产生的新 run_id 不代表新的逻辑工具调用，中断记录仍按发生时间保留。
- 记忆路径统一走 `/memories/` 的 StoreBackend；无沙箱时不安装沙箱技能加载钩子，普通对话仍可运行。
- Web API 需要 PostgreSQL 运行记录，初始化失败不宣称 ready。CLI 可使用内存历史；MCP、沙箱仍是可选能力。

## 本轮完成范围

重做聊天路由、附件准备、流转换、后台生命周期与核心错误处理；同步迁移审批恢复调用、业务输入错误，并补充并发、取消、流隔离、部分输出落盘和启动清理回归。

验证优先使用真实 LangGraph 与 SDK 消息。I/O 边界可以模拟；内部不要为宽松测试替身增加生产兼容分支。另用实际 HTTP 服务和隔离数据库空间验证启动、SSE、历史与状态落盘。

## 执行步数与主动收尾

`AGENT_RECURSION_LIMIT` 默认 125，限制图执行步数，并非模型调用次数。同步和 SSE 入口均显式传递图配置中的上限；否则 `astream_events` 补齐的默认值 25 会覆盖图绑定配置。

主 Agent 与显式配置的子 Agent 使用 `ExecutionBudgetMiddleware`：剩余步数不超过 12 时，下一次模型调用移除工具，要求说明已完成工作、文件位置和剩余工作。硬上限仍作为兜底。预算取自 LangGraph managed state，每次执行重新计算；继续发送消息即可使用新的预算。收尾不自动重放工具，也不代表整个业务任务已完成。

## 后续应独立处理

1. 沙箱服务仍有 SDK 输出猜测和重复路径/状态处理，应按实际 SDK 类型整理，并用真实沙箱验收。
2. 历史与工具结果仍保留旧消息及旧文本格式适配，应单独定义迁移边界，不能直接删掉已存会话的读取能力。
3. 指标、子任务持久化及审批模块仍有未标注类型的函数，应按数据模型逐块收敛。
4. 前端 store 的运行状态推导需另行统一；本轮保持现有事件协议，不重写 UI。

这些遗留部分不属于本轮已完成范围，不能以测试通过认定整个仓库已重写。
